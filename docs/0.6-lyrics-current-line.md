## Demonstrated work and change

`FoundationTimedLyricsView` on iOS and macOS derives its highlight from the
authoritative player's elapsed position through `FoundationLyrics.activeLine`.
The prior implementation first filtered the entire lyrics array into an eligible
array, then selected its maximum timestamp/ID. That expression runs as the clock
updates and when the user seeks backward or forward.

Selection now makes one pass over the immutable input with only a selected ID
and timestamp as local state. It creates no intermediate collection and does not
sort, cache or mutate the input. Both algorithms have linear time complexity;
the new selection uses constant extra space instead of an eligible-row array.
These are code-level work characteristics, not a measured application allocation,
frame-rate or CPU improvement. No percentage or whole-app smoothness claim is made.

The same contract is preserved:

- Elapsed time must be finite and nonnegative.
- Eligible starts are finite, nonnegative, no later than elapsed, and strictly
  before a positive duration. Nonpositive durations retain unknown-duration
  behavior; the prior nonfinite-duration comparisons are unchanged.
- The greatest eligible timestamp wins, regardless of source order. Equal
  timestamps select the greatest line ID, matching the previous comparator.
- Blank timed rows remain boundaries. Missing/invalid times are not candidates.
  Queries after backward seeking remain independent of earlier calls.

There is no change to lyric loading/cancellation/retry, the native player or seek
path, the intended five-second follow recovery, VoiceOver policy, accepted row
spacing/dimming or the bottom Follow Current Lyric button. There is no new task,
observer, timer, request, logging channel or playback-priority rule.

## Verification and remaining work

Four focused tests add independently named boundary expectations and a two-pass
reference of the prior selector across a synthetic 1,024-row mixed timeline.
The reference is test-only; production has one selection owner. The cases include
unsorted/duplicate starts, line IDs differing from source order, blank markers,
invalid starts, duration boundaries, nonfinite inputs and extreme integer IDs.

Formatting and whitespace checks pass. Compilation and the focused
`FoundationLyricsTests` suite are pending the coordinator's serialized build lane;
no Xcode, Simulator or physical-device action was performed by this source worker.
The remaining #153 account/track cancellation, error/missing/untimed, actual
highlight/seek/follow, compact layout, Dynamic Type, keyboard and VoiceOver checks
still require their exact-candidate evidence. Physical audible timing and native
scrolling must not be inferred from these pure selection tests.

All data in the added cases is synthetic. No media/account identifiers, private
origins, credentials or raw server responses are added to diagnostics or shared
evidence. No application installation, publication or release is authorized by
this local source slice.
