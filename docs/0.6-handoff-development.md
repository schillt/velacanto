Scope follows the live v0.6 issue and owner clarification: continue the full queue,
selected occurrence, ordered effective-visible occurrence IDs, current position, existing effective shuffle order, shuffle
flag and repeat mode. This implementation does not introduce another player or a
new account/provider system. Existing shuffle-off behavior does not reconstruct a
previous base order; Handoff preserves that existing behavior without reshuffling.

The complete raw queue and the source-visible occurrence subsequence are retained
separately. A narrow queue-owned visibility set preserves the source's effective
copy selection without changing receiver-wide preferences. Shuffle, repeat and
reorder retain that selection; removals prune their occurrence and explicit
additions extend it. Whole queue/context replacement retires it, and restoration
can restore its persisted snapshot. An explicit duplicate-copy preference change
retires it; ordinary metadata/availability refresh never resurrects hidden copies.
The optional snapshot field is backward compatible with prior stored queues.

The account-owned controller publishes one native NSUserActivity. A visible album,
artist or playlist detail temporarily owns its browse advertisement; leaving that
owner falls back to the playback session. Browse continuation resolves content using
the receiving device's own account and opens the existing destination without
changing playback. Playback continuation requires native confirmation before
replacing the receiving queue. A paused source remains paused after restoration,
and its deferred position does not load a playback resource until explicit Play.

The advertised versioned header is limited to 2 KiB. Its account/source digest,
transfer UUID, kind, schema and creation date contain no credentials or raw server
address. The full session travels over native Handoff continuation streams, capped
at 4 MiB and 10,000 occurrences. Queues over either limit are rejected whole;
there is no silent first-page transfer. Optional display strings are bounded and
playback URLs, local paths, artwork URLs/tags and account credentials are excluded.
Native stream work yields after 64 KiB, and bounded encoding/decoding runs outside
the UI actor. The exchange has a 30-second initial deadline and a maximum lifetime
of 120 seconds from opening, including user confirmation and playback start.

Only a correlated acknowledgement sent after actual native receiver playback starts
can pause the original source. The immutable transfer nonce, account lifetime,
original playback intent, native selection generation and occurrence must still
match. Cancellation, failure, absent acknowledgement or newer source/receiver
intent keeps the source's current intent. NSUserActivity continuation notification
alone is never used as playback evidence. There is no automatic transfer retry,
continuous synchronization or remote playback control. Retired advertisements
rotate their UUID so a later explicit Handoff uses a fresh request.

Account invalidation closes streams and clears incoming confirmations. Receipt
tracking is memory-only, bounded to 128 recent IDs and five minutes. The payload
freshness window is five minutes with 30 seconds of clock skew; a live source
refreshes the response timestamp while preserving its request UUID. Cold delivery
registers native streams synchronously, opens them before account readiness, and
requests queue bytes only after own-account authorization and scope matching.
