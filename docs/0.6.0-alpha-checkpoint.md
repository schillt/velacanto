## Known limits and next ownership

Pre-publication security review covered the 95 changed paths from published
`604d4d4a243e501ef197793f733fab7586ffddf3` to runtime309. No release-blocking
finding was identified. One low-priority resource-budget follow-up remains:
opt-in native HLS downloads do not enforce the app's ordinary receive-byte ceiling
while the OS downloads media. A malicious or compromised selected server can cause
excess disk/network use; OS failure/reclamation limits impact. This was established
by static control tracing, not a live storage-exhaustion experiment, and is tracked
in [#214](https://github.com/schillt/velacanto/issues/214). It does not
establish a credential or account-boundary failure. The full private review and
original severity hypothesis remain retained locally; no blanket security pass is
claimed. The separate documentation and Production archive configuration amendment
was independently reviewed and does not change installed runtime source.
