## Known gaps and excluded experiments

**Final native check scope:** the original 12-point filler row rendered at52
points; fixed-size did not resolve the native minimum. It was replaced at six List
owners with native scroll-content margins. Three actual native extent checks at
0/12/64 points passed without skips and preserved all natural row heights. An
intermediate virtualized fixture skipped all three and is retained, not counted as
a pass. Static review found no substantiated P1/P2 regression. These measurements
do not prove dynamic inset normalization or native bar transitions.

The bounded representative UI run executed four cases: **one passed, two failed,
one skipped**. The original Home icon visibly rendered and passed. The card's
metadata and initial guide steps completed, but the check failed waiting for
Handoff Help after guide suppression. The List cycle case failed because its
numeric accessibility snapshot was absent; no cycle behavior was measured. Home
underlap skipped because the visible native header could not be observed. These
are follow-up acceptance gaps, not green checks. No assertions were relaxed and
none was rerun to manufacture acceptance. Final source formatting passes with
zero findings; two empty test closures received explicit parameter labels only.

**Rendered/native acceptance remains pending.** In particular: actual List zero/positive
footer sizing; automatic minimized→expanded bar end retention on every affected
pane; midscroll underlap; deliberate upward scroll; late-content behavior; related
sheets; Home icon rendering; remote card metadata/guide/trash/swipe and horizontal
shelf gestures. The owner says Home end clearance is improved but its appearance
needs restoration; other panes still have reported bottom overlap. Unit tests do
not close these reports.

**Browser/other-client continuation is not included in this checkpoint code.** Its
separate prototype is uncompiled/unaccepted. Official Jellyfin Web source supports
its reported queue order, duplicates, selected occurrence, position and repeat.
The original shuffle toggle/backing order is not reliably exposed. The owner chose
best-effort automatic Stop after actual receiver start and a fresh matching source
check; Jellyfin cannot make the check/Stop atomic. This decision is recorded for
the pending implementation, not a claim it works in this alpha. Never show Apple
Handoff instructions as a browser transfer path or silently substitute one track.

**System Settings bulk download management is unresolved.** Its isolated proof
has25 passing allocation/projection unit tests. A fresh synthetic download/cache/

but the test skipped when it could not find General. No exact asset/title/artwork/

The proof/navigation experiments are not enabled in this application. The native
HLS/Original-quality/authentication/retention/active-file-lease dependency remains
before an accepted replacement can remove Profile's bulk manager.
