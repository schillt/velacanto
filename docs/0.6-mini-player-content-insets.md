## Demonstrated mechanism and correction

The current ASC0.5.0(30) screenshot shows final Home labels beneath the player.
A controlled iOS27.0 compact-bar end initially cleared the player. Expanding the
bar retained the old content offset and covered the final labels, reproducing
that visible failure shape. Scrolling again restored clearance while minimizing
the bar; that did not prove an unreachable final position in every state.

Native geometry confirmed a56pt viewport reduction. The system reserves the
additional chrome space, but publishes viewport and inset changes separately.
For the captured normal-text sequence, offset379 remained unchanged while the
container shrank629→573; bottom inset83→139 arrived in another callback.
`visibleRect` includes inset regions in this composition, so the effective visible
bottom is `visibleRect.maxY - contentInsets.bottom`. An earlier derived maximum
offset formula was discarded rather than used to invent padding.

`FoundationScrollEndPreservation` makes one framework-clamped point request when
the view was already at its unobscured end, content/width/top inset and offset
remain unchanged, the bottom-side viewport shrinks and the user is idle. Its
tolerance comes from the consuming view's display scale. It does not retain a
bottom-edge anchor that would follow independently published content. The shared
modifier is enabled explicitly on the outer Home scroll view only.

The first policy incorrectly required the inset increase and viewport reduction
in one callback. Bounded synthetic tracing identified the actual split sequence;
the correction permits a nondecreasing inset while retaining the other ownership
guards. Captured-vector tests cover atomic and split updates, no repeated request,
initial/middle positions, content publication, changed layout, active scrolling,
newer explicit position intent and pixel tolerance.

After that correction, normal-size UI passed. Accessibility3 exposed a separate
two-line label overflow beyond the native capsule, leaving a2.667pt control-bound
intersection despite the correct56pt position adjustment. The small label view
now adapts its line count at iOS accessibility sizes without capping the font or
changing the end-position policy. Full semantic metadata and Playing/Paused
updates are checked through native accessibility values.
