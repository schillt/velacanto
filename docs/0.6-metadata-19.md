# Song credits and metadata — issue 19 local slice

The live [GitHub issue 19](https://github.com/schillt/velacanto/issues/19) remains the
scope authority. This is a local implementation record, not issue completion,
installation, server acceptance or release evidence.

## Audited gap and implementation

The existing shared catalog item exposes title, album/artist references, genres,
duration and ordering, but no credits. The pinned Jellyfin SDK's `BaseItemDto`
already supplies `People`, `ProductionYear` and `Genres` on the existing GetItem
endpoint. The adapter previously discarded these credit/year fields.

Now Playing's More playback options menu opens Song Credits on iOS and macOS.
The existing related album/artist sheet owner now holds a related-or-credits
route; there is still one root sheet presentation. Both routes restore the
captured system appearance, with shared interactive/artwork dismissal guards.
Nested queue sheet ownership is unchanged. The credits sheet uses semantic
foreground colors, native List/NavigationStack and Done, a visible iOS drag
indicator, wrapping text and combined accessible credit rows.

The provider-neutral display model contains credit names, role labels, optional
role details, year and genre names. Jellyfin-specific mapping remains at the
adapter boundary. Composer, writer, producer, conductor, lyricist, arranger,
engineer, mixer, remixer, artist and album-artist types get meaningful labels;
other types remain Contributor, retaining the supplied role text. A person can
appear in several distinct roles; only exact duplicate displayed rows collapse.
Names are never split and person IDs are never treated as music-artist IDs or
links. Shared UI receives no provider DTO, identifiers, URLs or artwork payloads.

Opening the sheet performs one ordinary, cancellable GetItem for the captured
track. Playback priority is explicitly false. No discovery, library scan,
prefetch, artwork read, new cache, player mutation or audio dependency is added.
The adapter validates track kind, item identity and Audio response type. It caps
mapped People at128 and genres at32, filters blank entries, normalizes display
whitespace/control characters and bounds strings at256 characters. Omitted array
entries are disclosed. Years outside1–9999 are omitted without inference.

The view task uses a digest of server/account identity plus selected library,
track, offline state and retry generation. Scope changes immediately hide old
results; cancellation and request generation reject late publication. No metadata
persists beyond the sheet. Unsupported, offline, empty and failed requests have
distinct messages; failures require explicit Retry. Closing/reopening is an
explicit new read. Authentication and malformed responses remain failures.

Primary schema evidence: pinned Jellyfin Swift `BaseItemDto`, `BaseItemPerson`,
`PersonKind` and `Paths/GetItemAPI.swift`; also the official generated
[BaseItemPerson documentation](https://typescript-sdk.jellyfin.org/interfaces/generated-client.BaseItemPerson.html).
This does not promise that every server/library populates credits.

## Verification and remaining acceptance

Authored six synthetic tests: exact single GetItem request and ordinary admission;
role/detail/deduplication and identifier exclusion; empty and mismatched responses;
bounded optional values; error classification; cancellation after a transport
ignores cancellation; account/library scope separation (some assertions share a
test). No user fixtures or server credentials are used.

Source formatting/lint, project plist lint and whitespace checks pass locally.
No Xcode build, tests, simulator, server, device or installation action has been
run by this worker; the coordinator owns the serialized validation lane.
