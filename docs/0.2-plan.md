# Velacanto 0.2 plan

## Purpose

0.1.0 proved the complete Jellyfin listening path. Version 0.2 makes that
working app easier to change, test, and use by reducing the size and mixed
responsibilities of its SwiftUI presentation code. It is a focused architecture
and interface-quality release, not a second feature-release disguised as a
refactor.

**Baseline:** the `0.1.0` tag on `main` (`fed0a8c`). The `alpha` branch starts
from that exact release base.

## Scope

### Required

1. **Separate UI ownership.** Split root composition, Home, mini-player, Now
   Playing, artwork loading, and catalog screens into focused units without
   changing provider or playback ownership. (#33, #35)
2. **Remove current presentation defects.** Fix the macOS sidebar behavior,
   inconsistent album-art sizing, and content obscured by the Now Playing bar.
   (#40, #42, #45)
3. **Keep behavior diagnosable.** Classify persistence, cache, and playback
   reporting failures; retain privacy-safe diagnostics; document the important
   service and state contracts. (#36, #37)
4. **Prove the new seams.** Add focused tests around extracted state owners and
   run the required pull-request gate before promotion.

### Included only after the required work is stable

- Native Play and Shuffle entry points for album, artist, and playlist views.
  (#43)
- A macOS playlist section that fits the simplified sidebar. (#44)
- Small API-surface reductions that directly remove duplication encountered by
  the UI work. (#34)

### Deliberately deferred

- Favorites and editable playlists/queues (#11, #12): these are new product
  workflows, not prerequisites for a safe UI re-architecture.
- Playback-mode visibility (#41), forgiving search (#46), and playback polish
  such as gapless/crossfade or AirPlay work (#47): each deserves its own
  product and validation scope after 0.2.
- New providers, offline downloads, CarPlay, and public distribution remain on
  the later roadmap.

## Architecture guardrails

- SwiftUI surfaces own presentation and user intent only. They do not build
  Jellyfin requests, persist tokens, or control AVFoundation directly.
- `AudioPlaybackCoordinator` remains the app-lifetime playback owner.
- Jellyfin types and endpoints stay behind the provider/API boundary; UI and
  shared playback models continue to use provider-neutral values.
- Extract coherent concrete types. Do not introduce a screen framework,
  service locator, generic coordinator hierarchy, or configuration-driven UI.
- Preserve iOS and macOS native layouts. Shared behavior does not require the
  same view hierarchy on both platforms.

## Delivery order

1. Record the target ownership map and extract low-risk presentation seams.
2. Correct #40, #42, and #45 while those seams are being established.
3. Consolidate repeated catalog and artwork behavior only where it is truly
   identical; keep distinct platform behavior explicit.
4. Add failure handling and contract documentation at the owning boundary.
5. Add the contained #43/#44 improvements only if steps 1–4 are stable.
6. Run `./scripts/build.sh pr`, perform focused platform smoke tests, and
   review the resulting file sizes and dependency directions.

## Exit criteria

- Root composition, catalog presentation, artwork infrastructure, and playback
  presentation each have clear ownership and materially smaller change
  surfaces.
- The three current UI defects are fixed on their affected platform surfaces.
- No new UI code reaches into Jellyfin transport, credential storage, or
  AVFoundation.
- Important cancellation, cache, failure, and playback-lifecycle invariants
  are documented where they are enforced.
- Focused tests cover the extracted state owners, and the pull-request quality
  gate passes.
- A follow-up review finds no new P1 correctness/security issue and rates the
  affected UI and service boundaries as maintainable.

## Tracking

The v0.2 milestone uses #38 as the umbrella. Its required work is #33, #35,
#36, #37, #40, #42, and #45. #34, #43, and #44 are conditional additions; the
deferred work above must not silently enter the release.
