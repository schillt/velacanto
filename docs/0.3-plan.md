# Velacanto 0.3 plan

## Outcome

0.3 is the Native Player Foundation release. It completes the daily playback
interface across iPhone, iPad, and Mac and establishes neutral catalog, action,
queue, and playback contracts suitable for a later CarPlay presentation.

The internal preview checkpoint is August 19, 2026. Final release is gated by
the [0.3 acceptance matrix](0.3-stability-acceptance.md), not by the date.

## Required scope

1. **Neutral catalog and actions.** Replace general UI exposure to
   `JellyfinItem` with `MusicCatalogItem`, `MusicItemCapabilities`, and a focused
   `MusicLibraryProviding` boundary. Jellyfin account/connect UI remains
   provider-specific.
2. **Favorites.** Read, display, optimistically mutate, reconcile, and safely
   roll back favorite state across every visible representation.
3. **Editable playback context.** Add Play Next, Play Last, upcoming-item remove
   and reorder, shuffle, and repeat off/all/one while preserving queue identity,
   preloading correctness, system commands, and bounded restoration.
4. **Native player surfaces.** Complete Home, Library, Search, details, mini-player,
   Now Playing, and Up Next using platform SwiftUI navigation and presentation.
5. **Playback method.** Carry a neutral local/direct-play/direct-stream/transcode
   value through the prepared request and current playback state.
6. **Stability and quality.** Resolve album-grid restoration, add focused UI
   coverage, and complete accessibility, server, and device acceptance on all
   supported platform classes.

## Platform contract

- Require iOS/iPadOS 26 and macOS 26 for 0.3.
- Use native `TabView` and its system playback accessory on iPhone.
- Use adaptive system tab/sidebar behavior on iPad.
- Preserve the native macOS `NavigationSplitView`, global library search, and
  Profile footer.
- Use native lists, grids, toolbars, menus, context menus, swipe actions,
  sheets, inspectors, materials, typography, and SF Symbols.
- Keep Home, Library, and Search as the only primary destinations.
- Do not recreate Apple Music branding, ship fictional content, or build a
  custom design-system framework.

## Architecture guardrails

- Views own presentation and user intent, not endpoints, tokens, URLSession,
  AVFoundation, or audio-session policy.
- IDs remain opaque and source-scoped; never force provider IDs into `UUID`.
- `AudioPlaybackCoordinator` remains the app-lifetime playback owner.
- Jellyfin continues to negotiate playback through `PlaybackInfo`; the UI sees
  only neutral items, capabilities, playback requests, and transport kinds.
- Favorite state has one account-scoped mutation/reconciliation owner.
- Queue edits affect upcoming items only. History/current item remain fixed.
- Explicit queue order wins over late paging or preload completion.
- CarPlay remains a future consumer; 0.3 adds no target, scene, entitlement, or
  templates.

## Delivery order

1. Publish this planning package, actionable GitHub issues, milestones, and board.
2. Establish the neutral catalog/action contracts and resolve the scroll bug.
3. Add favorites and editable playback context with focused unit coverage.
4. Complete native Home/library/detail and Now Playing/Up Next presentation.
5. Add UI/accessibility coverage and perform platform/device/server acceptance.
6. Promote `alpha → beta → preview`; promote `preview → main` only after final
   acceptance.

## Deliberately deferred

- Offline audio, download/storage controls, and network-transition recovery.
- Playlist create/rename/delete and playlist membership editing.
- CarPlay implementation and casting.
- Forgiving search, gapless/crossfade, and AirPlay investigation.
- Multiple accounts, new providers, public distribution, and analytics.

## Definition of done

- All milestone issues are closed with verification evidence.
- iPhone, iPad, and Mac meet the native interface and accessibility contract.
- General music views no longer depend on Jellyfin transport models.
- Favorite, queue, playback-mode, and album-position behavior pass focused tests.
- The strict local and hosted gates pass on the exact candidate commit.
- The device/server matrix is complete or records explicit accepted limitations.
- Release documentation and version/build metadata match the promoted source.
