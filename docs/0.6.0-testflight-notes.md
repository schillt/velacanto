## Known release limits

- Local-file provider/composition work is unfinished and hidden from the main
  source controls; existing metadata groundwork is retained for later development.
- Existing Siri remains; no new App Intents/Apple Intelligence scope is promised.
- Mac Home scrolling can remain choppy. Broad iPad/accessibility/route/permission/
  account/fault and storage-pressure matrices are not claimed complete.
- Browser/server continuation depends on the reported queue and source control.
  One action continues the verified current song if no usable complete queue is
  reported. Source stopping is best effort; support differs by player/server.
- iPhone system Storage uses Apple's third-party native media list, including its
  generic video/watched labels. Apple Music's artist/album hierarchy is not claimed.
  Verified native acquisition used the selected AAC route; universal native Original
  and all-quality coverage is not asserted. Existing file-download behavior remains.
- Formal parked CarPlay head-unit verification is later. Supported audio-category
  browsing/Siri does not imply access to a navigation-only typed keyboard.
- Standalone-artist classification and specific per-track compatibility investigations
  remain open without speculative catalog scans or universal codec claims.
- Native system-managed HLS downloads have a low-priority receive/storage-budget
  follow-up from static review. Oversized media from a malicious selected server
  ([#214](https://github.com/schillt/velacanto/issues/214)) can consume more disk/network
  than the app's ordinary download ceiling before
  native OS failure, reclamation or user cancellation. No live exhaustion was tested.

The owner accepted these remaining older issues for future builds. Keep their
history and issue records open; do not turn deferral into implementation completion.
