## What this tranche does

`FoundationLocalCatalogIndex` runs filesystem work on its own actor. The caller
must supply a currently authorized, explicitly selected root and separate private
index storage. Refresh inspects at most25,000 entries and retains at most10,000
records. Index reads/writes are bounded to8MiB. File content is not read for tags,
artwork or playback; titles currently use the filename. Candidate audio extensions
identify index candidates, not a claim that every codec is playable.

Records use an opaque source UUID plus a SHA256 digest of volume/inode/birth-time
identity. Renaming a file on the same filesystem retains identity. A replaced file
or filesystem move can legitimately create a new record; the former occurrence
then becomes explicitly missing. Hard links share one identity and select the
lexically earlier relative path. No raw filesystem identifier or absolute music
path is persisted in a record. Relative paths and filenames remain private local
metadata; nothing is logged or synchronized.

The versioned JSON index atomically restores independently from Jellyfin accounts
and downloads. Missing roots preserve the prior persisted catalog and return an
unavailable result. Complete refresh marks missing records; bounded/incomplete
refresh retains earlier availability and reports partial instead. Empty, corrupt,
source-mismatched and oversized indexes have deterministic results. Corrupt
restore does not delete its evidence or silently scan a folder. An explicit
successful refresh may replace the index. The source/capability projection is
explicitly read-only; no mutation URL, file-writing action or write affordance is
provided.

The enumerator skips hidden entries, package descendants and symbolic links,
checks resolved descendant paths and requires regular-file attributes. It never
writes a music file. Index persistence inside the selected music directory is
rejected using resolved ancestry plus filesystem directory identity, including
symlink ancestors and equivalent case-insensitive aliases. The check runs before
restore, before directory creation and again before writing. These URL checks are
not a descriptor-relative atomic guarantee against concurrent path substitution. This remains a source-only implementation: filesystem race/provider
behavior and native sandbox scope enforcement require independent review and
actual platform verification before enabling folder indexing.

`FoundationLocalFolderAccess` creates native bookmark data and balances scoped
access around an asynchronous operation. macOS bookmarks request read-only scope;
iOS uses a minimal bookmark with security-scoped access obtained from the native
selection. Stale bookmarks or denied scoped access fail closed without a path
fallback. Bookmark ownership/persistence, reselect UI and the selected-source
lifetime are deliberately not guessed in this core.

Independent review identified two P2 source defects in the initial checkpoint:
lexical-only storage exclusion allowed a symlink ancestor to redirect persistence
into music, and a full newly scanned record set could evict prior occurrences at
the10k publication cap. The follow-up adds canonical/resource-identity exclusion
and prior-record-reserved merging with genuine regressions. These regressions
remain uncompiled/unrun until the coordinator grants the serialized test lane.

An actual combined Mac run then stalled during a valid separate-root refresh.
A five-second process sample located the hot loop in storage ancestry traversal.
A bounded standalone Foundation probe reproduced the specific URL behavior:
URLs derived from `FileManager.temporaryDirectory.appendingPathComponent` can
return `/..` as the parent of `/`, then keep adding parent components. Plain
file URLs did not reproduce that behavior. The helper now visits a strictly
decreasing finite set of path-component prefixes, retains resource-identity
containment, and is shared internally with the selected-source owner. A direct
regression covers separate temporary storage and filesystem-root termination.
The extracted exact helper passed four standalone Foundation checks; application
tests remain for the coordinator's serialized lane. No root-cause claim is made
for unrelated framework behavior.

The corrected full Mac suite completed736 tests with one real local-index
failure: the symlink-ancestor regression threw the expected rejection but its
directory-absence assertion failed. A preflight resolving the entire missing
destination had left the existing alias unresolved, allowing directory creation
before the later guard rejected it. The next correction resolves the nearest
existing ancestor with native `lstat`/`realpath`, then attaches the missing tail;
dangling, looping, non-directory or inaccessible ancestors fail closed. Both the
ancestor search and resource-identity checks use finite path prefixes. The
original directory-absence assertion remains unchanged; nested missing-tail and
dangling-link regressions are added. Six standalone Foundation/native-path checks
pass without index writes; the application regressions await a fresh lane grant.
This remains a repeated-check guarantee, not protection against an adversarial
concurrent path swap between checking and filesystem mutation.
