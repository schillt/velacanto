## Ownership direction

The app model admits one account runtime and injects the existing library, player,
actions, downloads, connectivity and system owners. Views own presentation and
visible demand. They do not create another player or own durable account cleanup.
Catalog values pass through scoped models/actions into presentation. Explicit Play
may expand a collection through the protected action path; ordinary queue additions
and browsing remain ordinary work. Audio/resource resolution does not wait for
optional artwork, profile or catalog publication.

Account retirement rejects late publication before replacement. Durable sign-out
also joins the work/finality required by its captured account scope before cleanup.
Cancelling work is not a drain. Retained music, disposable caches and local/cloud
pins have distinct removal contracts that file organization must preserve.

## Medium playback widget boundary (#227)

One medium WidgetKit kind exposes native Edit Widget modes Current Song and Recent Album/Playlist; separate instances can use each. Mode is a WidgetConfigurationIntent/AppEnum parameter, not a catalog picker or queue command. The extension projects one bounded, sanitized account-scoped record into the configured mode. Current and recent metadata coexist while a queue is active. The app retains the single player/resolver; the extension receives no credentials, media URL, queue database or network access.

The existing store owns one JSON record <=16KiB and two live immutable thumbnails <=256KiB/320px. Known crash/staging/orphan files remain inside the eight-entry maintenance/admission budget. Preflight preserves the committed record and both referenced images; a transaction publishes JSON only after all referenced new images exist and cannot roll them back after commit. Optional recent fields preserve valid v1 current data, and malformed optional reference/art pairs drop together. No queue/auth schema or account-data policy changes.

FoundationWidgetPlayback owns one coalesced metadata worker, one optional recent-art consumer and one latest desired reference. Metadata commits first; held recent art cannot block current data. Finished consumers retain their exact handles until joined before replacement. The storage actor fences owner generation, metadata sequence and per-slot artwork identity; enrichment merges into latest metadata. AppModel owns the in-memory widget generation, preventing retired flushes from reactivating after clear. No task chain or retired-owner history grows per update.

AudioPlaybackIntent uses existing app runtime admission. Current/matching-known-collection controls are exact-occurrence Play/Pause. Explicit recent collection start validates account and collection id+kind, allowing unrelated track advancement before the tap; it captures queue/runtime/account at admission and retains existing cancellation/commit fences against changes after the tap. One widget-owned request token and bounded command/completion observer additionally cancel only that request on a newer explicit Play/Pause/seek; other UI collection behavior is unchanged. It never infers playlist membership or claims a fake Resume. Accepted manual queue extension conservatively clears only the current collection-origin tag, retaining last played collection, queue/order and occurrence. Mixed queues therefore offer explicit recent collection Play rather than pretending unrelated appended songs belong to that collection; pure collection playback still supports matching occurrence control. The existing optional origin field persists this unknown value, with no per-occurrence map/schema or Handoff payload change. Shared private selection also invalidates only that presentation tag when moving to an earlier raw queue position, covering Back/history and Repeat All wrap. Same-occurrence restart and normal forward pure-collection playback keep matching control. Even a pure-collection backward/wrap route conservatively loses the matching optimization rather than guessing membership; Recent remains explicit Play Collection and Current Song still controls the exact song. Queue IDs/order/selection/audio and saved/Handoff schemas are unchanged. Metadata-only flush precedes intent return without joining artwork/audio/queue producers. Publication failure returns an explicit acceptedWithPublicationFailure outcome and does not undo or misreport an already accepted media command.

Retirement closes publication synchronously and joins both exact owned tasks before structured shared-store cleanup. Cache producer/native finality remains owned by existing cache/download owners. Pending/failed reauthentication retains accepted data; widget clear failures remain reported and retryable. App Group entitlement/target scope and isolated disposable roots/no-op reload remain unchanged. OS timeline caches can lag; signed configuration/gallery, cold/background/locked dispatch and account-state checks remain physical acceptance work. No post-return OS audio execution-grant guarantee is inferred from source or isolated tests.

## Offline catalog/search value boundary (#202)

`FoundationOfflineCatalogProjection` shapes value arrays for unique downloaded songs, expanded/remembered container precedence, related albums/artists, kind-safe catalog identity, existing localized search and bounded pages. It retains no state, manifest, collection model, callback, task or storage handle. Inputs and results are value types. This is a responsibility boundary, not a new cache or a scheduling/performance change.

`FoundationDownloads` remains the only account-owned manifest/readiness/transfer authority. It captures live/storage/inventory and exclusion predicates, expanded and eligible remembered seeds, current canonical availability and the existing visibility projection at their prior call boundaries. Canonical collection-model/saved-snapshot precedence, bounded persistence/reconciliation, playback leases, native transfer retirement, deletion and account cleanup remain there. Remembered discovery metadata never gains a file-retention claim. The public facade and its UI/Siri/CarPlay consumers keep their existing signatures.

Pure grouping/search tests are members of both normal and isolation suites. Existing facade download tests need explicit coordinator-selected execution; the isolation suite does not acquire the whole Downloads test file implicitly. Source-only review, compilation, synthetic outcomes and exact signed-device offline/playback acceptance are separate evidence. No speed improvement or whole-issue acceptance follows from extraction.
