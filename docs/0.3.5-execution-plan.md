# Velacanto 0.3.5 execution plan

Owner-approved direction, 2026-09-22. This is a preparation and execution contract,
not a claim that runtime features are implemented. GitHub issues, integrated
commits and exact-candidate evidence are authoritative. No release date is set.

## Baselines and decision

Preserve released 0.3.0 (108), source
`df23cfcb7df3edc2fcf375988399a816c6d1aa0f`, and Foundation 106 behavior reference
`3d66dbe8c9f0119f935c466585bd048f4e4d15b2`. Build 107 remains rejected.
Planning starts from alpha `abab2f78f8c2b545ae31acb1751cdeee3d559cd1`.

Keep the existing AVPlayer. Correct native playback outcomes and background
handoffs before combining controls. Adopt Apple's **NowPlaying framework** on
OS 27 through one retained MediaSession and a representation of the existing
player. Do not install a parallel legacy MediaPlayer command-registration stack.
Native volume APIs remain appropriate; this decision concerns system metadata
and commands. See [Apple's introduction](https://developer.apple.com/videos/play/wwdc2026/312/).

#160 reproduced background successor start rejection (`setRateFailed`) and stale
playback intent. The OS-level reason remains unresolved. Catalog requests succeeded
while playback was paused; this does not reproduce #159's separate app-wide
network-loss report. Neither NowPlaying nor async activation is a proven cure.

## Ownership contract

| Responsibility | Owner |
| --- | --- |
| Queue occurrences, playback intent, native item lifecycle | Existing player |
| Audio activation/deactivation and interruptions | One serialized playback-owned lifecycle |
| Authenticated catalog, artwork, mutations and later reporting | Existing Jellyfin adapter |
| Native streaming and buffering | AVPlayer |
| System metadata and explicit remote commands | One retained NowPlaying owner, account teardown |
| iPhone/iPad output volume and route UI | MPVolumeView and native route picker |
| Mac player gain | Existing AVPlayer, honestly labeled |
| Screen loading and optional lyrics | Explicit retained model/task owner |
| Current artwork | Shared bounded owner consumed by UI and system representation |

Redraw, sheet presentation, metadata refresh and volume cannot replace a player
item, activate audio or start catalog/artwork requests. Commands call explicit
player operations; waiting is not identical to failed start. Account, selection
and seek generations reject obsolete results. Optional failures stay local.
Preserve delivery parameters until deployed Jellyfin/pinned SDK semantics and a
reproduced defect justify change. No watchdog, retry loop, session reset, global
scheduler, prefetch or new transport by default.

## Reusable grading and clean-code guardrails

Historical 0.3 grade: **78/100, C+**, a previously recorded baseline assessment with
limited physical/distribution evidence. It is not a newly recomputed grade and
must not be assigned to 0.3.5. Preserve original per-category audit evidence when
publishing historical documents; do not fabricate missing subscores.

For future candidates score each category 0–100, attach evidence and uncertainty,
then apply these weights: correctness 30%; async/network reliability 25%; architecture
and ownership 20%; maintainability 10%; tests/build/distribution 10%; accessibility 5%.
Bands: A 90–100, B 80–89, C 70–79, D 60–69, F below60; plus for top three points and
minus for bottom three points within B/C/D. Any unverified gate stays pending even
if the score is high. Use this rubric consistently for future candidates; changing
weights requires an explicit versioned rationale, not retroactive grade inflation.

Require abstractions justified by current responsibilities, complete async
outcomes, explicit lifetime/teardown, and tests that catch behavior failures.
Avoid speculative extension points, generic managers, duplicate state machines,
warning suppression and comments that narrate obvious syntax. Function docs should
be concise multiline blocks describing contract and nonobvious ownership or
cancellation behavior. Keep P3 formatting/proven-unused-code removal separate from
runtime fixes; flag structural concerns instead of folding them into polish.
