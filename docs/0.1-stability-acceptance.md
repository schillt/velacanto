# Velacanto 0.1 stability acceptance

This matrix is the final release gate for the 0.1 performance, artwork, and
playback stabilization work. Automated checks prove the implementation compiles
and its isolated behavior is covered; the device/server checks prove the
experience under real media and network conditions.

## Automated evidence

As of 2026-07-30:

- Swift formatting lint passes.
- The macOS app builds.
- All 54 macOS foundation tests pass.
- The iOS Simulator app builds.
- An iPhone Air simulator build compiles, installs, and launches.
- A signed physical iPhone build compiles.

Re-run the project checks before tagging the release:

```sh
./scripts/build.sh all
```

## Physical-device and server matrix

| Area | Required verification | Release criterion |
| --- | --- | --- |
| Cold browse | Open Albums, Artists, Songs, Playlists, details, and Search after clearing caches. | Useful first content appears within 2 seconds on a normal local-network Jellyfin server. |
| Warm browse | Reopen previously visited categories and details. | Cached useful content appears within 0.5 seconds and revalidates without clearing it. |
| Pagination | Scroll each large category and a large album or playlist repeatedly. | The next page arrives before the end, order remains correct, and no duplicate rows appear. |
| Search | Type and rapidly revise category and global queries. | Results represent the full server library after the debounce; stale requests do not replace newer results. |
| In-app artwork | Open, close, rotate, background, and foreground full Now Playing during several tracks. | Artwork never flashes back to the placeholder during elapsed-time updates. |
| System artwork | Lock the device and inspect Lock Screen, Control Center, Bluetooth, and AirPlay surfaces. | The active track's cover appears and always matches its metadata. |
| Rapid track changes | Skip quickly across tracks with different covers, including while artwork is cold. | A delayed prior request never replaces the current cover. |
| Playback start | Start several cold and warm Jellyfin streams. | Audio becomes audible within 2 seconds on a stable local network. |
| Queue controls | Exercise previous before and after 3 seconds, next, automatic completion, queue boundaries, and a page boundary in Songs/Search. | Controls follow contextual order; previous restarts after 3 seconds and otherwise moves backward. |
| Relaunch | Quit during playback, relaunch, and inspect Now Playing before pressing Play. | Metadata and position restore immediately in a paused state; Play resolves a fresh stream and resumes near the saved position. |
| Network recovery | Interrupt the network during playback, then restore it. | A transient terminal failure performs at most one fresh-stream retry and never loops indefinitely. |
| Audio routes | Test an interruption and remove wired or Bluetooth headphones. | State and position are saved; playback resumes only when permitted and pauses on route removal. |
| Cache behavior | Revisit stale cached metadata and artwork, then log out and sign into another account. | Stale content revalidates cleanly; the previous account's metadata, artwork, and saved Now Playing do not appear. |
| Lifecycle reporting | Inspect Jellyfin's active-session state while starting, seeking, pausing, advancing, and ending playback. | Start, progress, pause/seek, stop, and end are represented; reporting failure never stops audio. |
| Long playback | Play a representative queue for 30 minutes on a stable network, including screen lock. | Playback has no app-caused stalls, artwork remains stable, and queue advancement succeeds. |

Record the device model, OS version, Jellyfin server version, network type,
source codecs, transcode/direct-play outcome, and any failed row with reproducible
steps. A 0.1 tag requires every row to pass or to be explicitly documented as an
accepted known issue.

| Long playback | Pass, device | The user completed the 30-minute locked-device playback test successfully. |

Failures found during this pass were resolved rather than accepted:

- Local HTTP IPv6 parsing now validates actual loopback, unique-local, and
  link-local addresses instead of trusting text prefixes.
- Lifecycle reports are ordered and use the same server-issued play session as
  the negotiated stream.
- Universal-audio fallback parameters are no longer misreported as proof of
  transcoding; the server's negotiated media-source result determines the play
  method.
- Restored Now Playing state now retains total duration while remaining
  compatible with state saved by older builds.
- Physical headphones testing found that a route-policy pause could be undone in
  the UI by a late AVPlayer waiting or playing observation. The coordinator now
  holds that explicit pause until the user resumes and cancels an in-flight
  audio-session activation; focused regression coverage protects the behavior.
- The app transport control now treats only audible playback as a pause state.
  In AVPlayer loading or waiting states it sends a resume/retry request, matching
  the working hardware play command instead of issuing another pause.
- Physical diagnostics identified the remaining route-recovery block: Bluetooth
  loss could begin an audio interruption without sending its end event. An
  explicit in-app Play after that route loss now clears only that route-recovery
  interruption state, reactivates the session, and was confirmed working on the
  connected iPhone.
- The Jellyfin *Endless Summer* version of The Beach Boys' California Girls
  advanced while AVFoundation kept reporting a `0:00` duration, disabling its
  seek slider. Playback items now retain the server's `RunTimeTicks` duration
  as a fallback until AVFoundation supplies one. The simulator confirmed the
  slider at `2:42`, a forward seek to `2:27`, and continued playback to `2:41`.

The outstanding rows above are explicit 0.1 acceptance gaps, not passing
results. Quantified performance timing remains to be completed or consciously
accepted before tagging 0.1.0.

## 2026-08-04 acceptance review

The release owner confirmed the following review groups as Pass:

- iPhone acceptance: browse and search behavior, artwork surfaces, playback,
  queue/seek behavior, audio routes, lifecycle reporting, and locked-screen
  playback.
- Non-production Jellyfin review: the required negative paths and recovery
  behavior.
- macOS review: connect, sign in, browse, playback, relaunch, and artwork.

This acceptance review supersedes the partial July 30 results for release
control. The release owner accepted the observed browse and playback
performance, pagination, overlapping-search behavior, system artwork, queue
boundaries, seek reporting, and negative-path evidence.

GitHub Actions run `30940548441` passed every quality-gate step for application
candidate commit `28ed174`. A local rerun of `./scripts/build.sh all` and
`./scripts/build.sh pr` also passed on 2026-08-04 with Xcode 27.0 beta.

The optional iOS Simulator runtime suite continues to fail seven tests covering
injected audio-session interruption, route-recovery, and system-command events.
The corresponding physical-device scenarios passed and the hosted gate retains
macOS unit tests plus an iOS warning-as-error compile. This simulator limitation
is explicitly accepted for 0.1 and remains documented in
[known issues](known-issues.md).

The 0.1.0 candidate is cleared for promotion to `main` and tagging.
