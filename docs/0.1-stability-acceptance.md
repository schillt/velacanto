# Velacanto 0.1 stability acceptance

This matrix is the final release gate for the 0.1 performance, artwork, and
playback stabilization work. Automated checks prove the implementation compiles
and its isolated behavior is covered; the device/server checks prove the
experience under real media and network conditions.

## Automated evidence

As of 2026-07-29:

- Swift formatting lint passes.
- The macOS app builds.
- All 37 macOS foundation tests pass.
- The iOS Simulator app builds.
- The generic iOS-device build compiles without code signing.

Re-run the project checks before tagging the release:

```sh
./scripts/build.sh all
```

## Physical-device and server matrix

| Area | Required verification | Release criterion |
| --- | --- | --- |
| Cold browse | Open Albums, Artists, Songs, Playlists, details, and Search after clearing caches. | Useful first content appears within 2 seconds on a normal local-network Jellyfin server. |
| Warm browse | Reopen previously visited categories and details. | Cached useful content appears within 0.5 seconds and revalidates without clearing it. |
| Pagination | Scroll each large category and a large album or playlist repeatedly. | The next page arrives before the end, order remains correct, and no duplicate rows appear. |
| Search | Type and rapidly revise category and global queries. | Results represent the full server library after the debounce; stale requests do not replace newer results. |
| In-app artwork | Open, close, rotate, background, and foreground full Now Playing during several tracks. | Artwork never flashes back to the placeholder during elapsed-time updates. |
| System artwork | Lock the device and inspect Lock Screen, Control Center, Bluetooth, and AirPlay surfaces. | The active track's cover appears and always matches its metadata. |
| Rapid track changes | Skip quickly across tracks with different covers, including while artwork is cold. | A delayed prior request never replaces the current cover. |
| Playback start | Start several cold and warm Jellyfin streams. | Audio becomes audible within 2 seconds on a stable local network. |
| Queue controls | Exercise previous before and after 3 seconds, next, automatic completion, queue boundaries, and a page boundary in Songs/Search. | Controls follow contextual order; previous restarts after 3 seconds and otherwise moves backward. |
| Relaunch | Quit during playback, relaunch, and inspect Now Playing before pressing Play. | Metadata and position restore immediately in a paused state; Play resolves a fresh stream and resumes near the saved position. |
| Network recovery | Interrupt the network during playback, then restore it. | A transient terminal failure performs at most one fresh-stream retry and never loops indefinitely. |
| Audio routes | Test an interruption and remove wired or Bluetooth headphones. | State and position are saved; playback resumes only when permitted and pauses on route removal. |
| Cache behavior | Revisit stale cached metadata and artwork, then log out and sign into another account. | Stale content revalidates cleanly; the previous account's metadata, artwork, and saved Now Playing do not appear. |
| Lifecycle reporting | Inspect Jellyfin's active-session state while starting, seeking, pausing, advancing, and ending playback. | Start, progress, pause/seek, stop, and end are represented; reporting failure never stops audio. |
| Long playback | Play a representative queue for 30 minutes on a stable network, including screen lock. | Playback has no app-caused stalls, artwork remains stable, and queue advancement succeeds. |

Record the device model, OS version, Jellyfin server version, network type,
source codecs, transcode/direct-play outcome, and any failed row with reproducible
steps. A 0.1 tag requires every row to pass or to be explicitly documented as an
accepted known issue.
