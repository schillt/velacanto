## Demonstrated failure and correction

Synthetic album playback followed by Now Playing → View Artist → explicit
collection Play/Shuffle produced an error or empty result in the existing action
owner. The native root outcome alert did not appear, and the presented player/
related-sheet stack disappeared. The model probe confirmed the actual completed
outcome before the failed alert lookup; this was not inferred from a missing tap.
The underlying selected occurrence, playback intent and native playing state were
preserved. Original runs and sanitized synthetic captures remain local.

The native outcome presentation now follows the existing collection-operation
owner to its visible surface. Home, Search, Library indexes, Favorites and canonical
catalog/track details use one shared modifier; the root handles actions without a
screen owner. Canonical Now Playing related details reuse those same owners and
presentation code. Only the matching visible owner can present its outcome.

An immutable outcome snapshot is derived from existing action state. Guarded
Retry/Dismiss reject stale snapshots after owner retirement, replacement or a newer
operation. An opaque revision distinguishes a newer identical error from the same
owner; it does not own work or add another lifecycle state machine. Existing
non-view action APIs, sequential expansion, cancellation, player ownership and
request admission are unchanged. Normal preparation remains quiet.

## Boundaries and remaining acceptance

The synthetic scenarios and model probe require the existing DEBUG iOS Simulator
harness, isolated UI-testing identity and valid run identifier. They do not connect
to a real account/server, alter personal libraries or enter shipping Release code.
No app identity, credential policy, quality setting, media transport, cache budget,
player/task ownership, version or Apple workflow changes are included.

This patch does not close the entire [#165 contract](https://github.com/schillt/velacanto/issues/165).
Broader Home/New/Library/Favorites/Search menu coverage, physical VoiceOver and
keyboard/pointer checks, and actual audible background playback remain separate
acceptance work. The owner's distinct nested recommendations/navigation report
in #206 is not attributed to this reproduced outcome-presentation failure.
Follow [playback protection](playback-protection.md); only playback and Now Playing
receive special priority, and audio must remain independent of optional content.
