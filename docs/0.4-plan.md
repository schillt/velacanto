## Major features

| Issue | Approved outcome |
| --- | --- |
| [#64](https://github.com/schillt/velacanto/issues/64) | Native create/rename/delete/add/remove playlist tracks. Preserve duplicate membership, permissions, cancellation/errors and active playback. Server reorder is deferred; #114 stays superseded. |
| [#12](https://github.com/schillt/velacanto/issues/12) | Upcoming-only removal/reorder, persistent shuffle/repeat and paused restoration of entries/selection/modes. No saved position; explicit Play begins selected track at zero. History/current are immutable. |
| [#13](https://github.com/schillt/velacanto/issues/13) | Original native-playable track/album/playlist downloads; Wi-Fi default, cellular opt-in, progress/cancel/explicit retry, On Device view and storage/removal controls. Unsupported/incomplete items remain honestly unavailable. |
| #13 downloaded playlists | Automatically reconcile membership/order on launch, foreground return, restored allowed connectivity and successful app edits. Download additions; delete files only when no other download retains them. No continuous polling or offline mutations. |
| [#14](https://github.com/schillt/velacanto/issues/14) | Measured bounded artwork reuse, offline placeholders, storage/account cleanup policy through the existing artwork owner; no legacy cache or speculative prefetch. |

One player resolves ready downloads to local files. Successful sign-out/account replacement removes account-owned media/metadata and saved sessions; cleanup failures remain visible. Persist no credentials or authenticated URLs in manifests. Failed sync preserves usable local content; shared files remain until all download owners release them. Low storage stops affected transfers visibly instead of silently evicting retained music. Defer deleting a playing file until the player releases it.

## Sequence and acceptance

1. Reconcile contracts and baseline evidence; establish storage policy.
2. Implement playlist lifecycle and queue editing independently; integrate accepted work serially and complete collection outcomes.
3. Implement downloads and automatic playlist reconciliation on integrated lifecycle/storage boundaries, then supporting reporting/favorites.
4. Finish remaining checks, freeze an exact candidate and coordinate internal distribution. Resolve P0/P1 or obtain explicit owner disposition.

Test production seams for duplicates, ordering, stale/cancelled results, errors/permissions, restoration and account cleanup. Downloads cover interruption/corruption, pressure, connectivity policy, local seeking and shared retention. Sync covers membership/order changes, failed refreshes and coalesced triggers. Real mutations use explicitly authorized disposable test libraries.

Use regular Xcode and serial build/device slots. Record iPhone 13 mini, iPad and signed Mac evidence separately; iPhone 17 Pro stays excluded. Request owner assistance for gates automation cannot establish, including physical audibility/routes. Compiler, simulator and Mirroring screenshots do not prove server mutation or TestFlight availability. Keep shared evidence sanitized.

Every build improves touched UI/stability flows. Major bugs/enhancements retain milestone/Project issues; broad accessibility/performance/maintainability retains separate tracking. Excluded: server playlist reorder, collaborative/offline editing, converted downloads, local-library indexing, new providers, CarPlay and public/main release promotion.
