## Existing behavior and concrete gaps

`NativeFoundation/Sources/FoundationSiri.swift` is entirely `#if os(iOS)`.
It handles `INPlayMediaIntent` through the containing application's delegate,
using the current account/library/player/actions and an intent/session guard.
It supports explicit named track/album/artist/playlist lookup, disambiguation,
shuffle and resume. Queue insertion, nondefault speed and repeat requests are
currently rejected. Lookup is bounded to50 direct results per requested kind,
at most four kinds; incomplete results cannot silently become a unique match.
Explicit Play resolution uses existing playback admission. Local-only lookup
uses the app's local projection. No second player is created.

`NativeFoundation/Intents/IntentHandler.swift` is an iOS-only extension. Its
legacy resolution route honestly reports unavailable, and handle requests return
`handleInApp`. It does not read credentials or instantiate playback. The app
declares Siri and CarPlay entitlements on iOS; the Mac sandbox/network/Keychain
entitlements do not declare the same Siri entitlement. Those facts do not prove
any new API needs additional entitlements.

There are no current `AppIntent`, `AppEntity`, `AppShortcutsProvider`, interaction
donation or upcoming-media donation implementations under the app/extension source.
The existing `FoundationSiriTests` cover authorization, bounded matching,
ambiguity, request rejection and stale command/account ownership; they were
inspected, not rerun for this documentation change. Mac has system transport via
the existing Now Playing bridge, but no equivalent named-catalog Siri handler.
Transport control support therefore does not establish catalog or discovery parity.

## Supported native paths

| Path | Concrete role | Decision for this development round |
| --- | --- | --- |
| Existing SiriKit media | Named media playback and existing CarPlay/Siri routing on iOS | Preserve; regression-test alongside new paths |
| App Intents + App Shortcuts | Explicit reusable actions in Shortcuts/Siri/Spotlight | Suitable first cross-platform tranche; propose Resume and Play a selected playlist |
| Media Intents + audio schemas | Structured Siri audio search and schema-backed playback | Prototype against current SDK and an eligible Mac before selecting production routing |
| Entity/Now Playing context donation | Associate current content with a system-recognizable entity | Add only after account-scoped entity resolution and deletion policy are verified |
| Station generation, recognition or custom AI | New music behavior rather than existing app actions | No supporting product implementation; do not advertise or fabricate it |

Apple's current native route is `AudioSearch` delivered to an `IntentValueQuery`,
audio-domain entities and a `.audio.playAudio` intent. It is not a reason to
replace SiriKit or use an AI model to guess catalog matches. See Apple's
[audio-search integration](https://developer.apple.com/documentation/mediaintents/responding-to-audio-search-and-playback-requests)
and [audio schemas](https://developer.apple.com/documentation/appintents/app-schema-domain-audio).
The local Xcode27.1 SDK confirms `MediaIntents.AudioSearch` on iOS/macOS27,
with `unspecified`, `searchQuery(String)` and `url([URL])` criteria. Both platform
SDKs contain the module. API presence is not proof of Siri routing or availability.

For playback intents use `AudioPlaybackIntent`, not the deprecated
`AudioStartingIntent`. For runtime modes use `supportedModes`; the local SDK
marks `openAppWhenRun` deprecated in26. App Shortcuts are extracted by the system;
static product phrases must contain the application-name token, with no personal
catalog names compiled into phrases. See [AudioPlaybackIntent](https://developer.apple.com/documentation/appintents/audioplaybackintent),
[App Shortcuts](https://developer.apple.com/documentation/appintents/app-shortcuts)
and [runtime modes](https://developer.apple.com/documentation/appintents/getting-started-with-the-app-intents-framework).

The macOS27 release notes record audio-schema routing issue177198033 and recommend
an `IntentValueQuery` accepting `AudioSearch` or Spotlight indexing. This supports
testing the query route before adding a broad persistent catalog index; it does
not establish that the issue exists on the installed Mac's exact OS build.
See [Apple's release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes).

## Proposed implementation contract

1. Add a small cross-platform App Intents file in the main app target. Keep the
   existing extension and SiriKit entry points. The system-facing code delegates
   to one account-owned action seam around the existing app model/actions/player;
   it must not introduce a second playback owner or access legacy credentials.
   Shared `FoundationApp`, player and project edits require coordinator ownership.
2. Expose Resume and Play Playlist as the initial user actions. Resume requires
   an existing selected occurrence and preserves queue/position/modes. Play
   Playlist resolves a chosen current-account entity and uses the existing
   explicit collection Play path with cancellable expansion. Report sign-in,
   unavailable, empty and ambiguous states honestly. Do not replace a newer user
   queue/transport intent after async resolution. Offer only these useful actions
   as initial App Shortcuts; add Open Playlist only when the shared native route
   is verified on both platforms.
3. Start with a lightweight playlist entity: an opaque account-scoped reference,
   title and minimal display data. Add track/album/artist schema entities for the
   audio-search prototype as needed. The identifier includes an opaque scope
   discriminator and kind; no token, server origin, file URL or raw account ID.
   Re-resolve every saved entity under the currently authenticated account and
   reject old scopes, even when provider item IDs happen to match. Do not return
   a different item merely because it has the same title.
4. Entity identifier restoration is bounded to requested identifiers. Suggestions
   use a bounded existing loaded/pinned projection, not a whole-server scan.
   Entity browsing/discovery stays ordinary admission. Only an explicit playback
   action may promote the resolution required for that Play. Incomplete/ambiguous
   search must stay incomplete/ambiguous; preserve duplicate occurrence policy.
5. The audio prototype implements `IntentValueQuery<AudioSearch>` with bounded
   search results and a schema-backed Play action. `searchQuery` can use existing
   exact matching/disambiguation. `unspecified` must offer a real bounded choice
   rather than inventing a recommendation. `url` must initially return unsupported
   unless a documented owned share-link route exists; never fetch arbitrary
   supplied URLs, treat them as playable resources or import credentials.
6. Set an explicit authentication policy per action after locked-device tests.
   Preserve current safe lock-screen transport behavior. Account/private-content
   actions must satisfy their data-protection and user-intent boundary; do not
   accidentally inherit AppIntent's `alwaysAllowed` default. Apple's
   [authentication policy](https://developer.apple.com/documentation/appintents/intentauthenticationpolicy)
   distinguishes authentication on either device from local-device unlock.
7. Do not add full-library Spotlight indexing or donate personal entities yet.
   A saved entity or system donation may outlive app sign-out. Before enabling
   either, implement/verify account-switch and sign-out revocation and state the
   remaining system retention boundary. Entity displays intentionally disclose
   media titles to the invoked system surface; exclude private URLs, credentials,
   playback history and local paths. No diagnostic log may record query/title/ID.
   Now Playing can later associate entity identifiers using Apple's documented
   [contextual-cue API](https://developer.apple.com/documentation/appintents/providing-contextual-cues-to-apple-intelligence-and-siri).

No capability or entitlement change is assumed necessary by this evaluation.
Prototype metadata extraction, signed entitlement comparison and actual routing
must determine requirements. Do not reuse the iOS Siri extension on Mac or add an
App Group merely to expose credentials to a new extension.

## Exact-device acceptance and selection gate

iPhone13mini can test existing SiriKit, ordinary App Shortcuts discovery and
execution, lock states and audio behavior. It cannot establish Apple Intelligence
or Siri AI availability: Apple's supported iPhone list starts with15Pro and16
families. A supported Apple-silicon Mac is the available candidate for modern
audio routing; record its actual model, OS build, language/region, Siri mode and
enabled state before making a support claim. No settings, enrollment, agreement
or account changes are authorized by this document. See Apple's current
[device requirements](https://support.apple.com/en-us/121115) and
[Siri AI requirements](https://support.apple.com/en-us/127893).

| Evidence required | Cases | Current result |
| --- | --- | --- |
| Pure action/entity tests | Restored stale scope; sign-out during held query; repeated IDs; empty/ambiguous/incomplete results; oversized/control input; unsupported URL; cancellation/newer queue intent | Missing for new APIs |
| Build and metadata | iOS/Mac Debug and signed Release; warnings-as-errors; extracted intents/phrases; diagnostic exclusion; unchanged required capabilities | Not run |
| Ordinary App Shortcuts | Actions appear; parameter discovery; warm/cold app; cancelled choice; exact playlist; no selected Resume; signed out; offline/local-only; locked/unlocked | Not run |
| Existing Siri/CarPlay | Basic resume/transport/named Play and disambiguation remain functional; no duplicate handler/player/start | Existing behavior preserved by docs-only change; no new runtime check |
| Modern Siri audio on eligible hardware | `AudioSearch` reaches the intended query; selected entity reaches Play; exact kind/account; ambiguity; unsupported URL; unsupported/disabled AI path | Not run |
| Physical playback/parity | Audible selected result; current queue/modes; cancellation beats late result; browsing/Now Playing responsiveness; background/seek/next/route when affected on both platforms | Not run |

Recommendation: select the two-action App Shortcuts tranche after a source
ownership/review handoff, and evaluate native audio-schema routing on the eligible
Mac independently. Do not promise cross-platform named Siri or Apple Intelligence
parity until these rows have exact-candidate evidence. Issue199 remains open;
the coordinator/owner must record an actual implementation selection or explicit
later-milestone disposition. Documentation alone does not clear the release gate.
