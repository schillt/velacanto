# Velacanto 0.3 known issues

| Area | Current behavior and limitation |
|---|---|
| System media | App-provided Control Center/Lock Screen metadata and remote commands are excluded. Build 107 failed physical reliability testing despite passing local checks. |
| Volume and AirPlay | In-app volume adjustment and AirPlay selection are unavailable. Disabled presentation must not be described as operational controls. |
| Lyrics | Disabled. Earlier correlation with failures did not isolate lyrics as the cause. |
| Server history | Playback-start, progress, and stop reporting are not implemented. Jellyfin history and play-count shelves may not reflect listening in this app. |
| Network recovery | Device/network failures remain an open investigation. The build 106 baseline does not establish that every outage recovers without a reset. |
| Media compatibility | Universal delivery permits direct playback or conversion; it does not guarantee every file plays or seeks. Track-specific failures require a reproducible, sanitized case. |
| Ranking and metadata | Artist grouping and suggested items depend on Jellyfin metadata. Most Played Albums uses a bounded sample, not a complete library ranking. |
| Queue and playlists | Playing, viewing, and adding items are supported. Legacy queue restoration, arbitrary drag reordering, playlist editing, and persistent shuffle/repeat modes are not included. |
| Providers and offline | Jellyfin only. Local libraries, additional providers, downloads, and offline playback are deferred. |
| Platform coverage | iOS and macOS are build targets. Compilation does not establish complete iPad, older-OS, accessibility, route, or device coverage. See the acceptance record. |
| Upgrade | The production bundle identifier is restored. Fresh sign-in is expected; no old-app credential migration is performed. |

When reporting a failure, include the build, the preceding actions, whether existing audio continued, and whether recovery required an app restart or network reset. Preserve the journal before resetting when practical. Share aggregate/redacted evidence rather than raw logs, credentials, server addresses, or personal media details.

Legacy issue history remains useful, but old issues should be closed only against their actual acceptance criteria. Recreated visual similarity does not prove that removed legacy behavior shipped. Deferred features and rejected experiments remain distinct from completed release work.
