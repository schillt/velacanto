# Isolated account lifecycle quality gate

The coordinator owns native execution and the dedicated iPhone Duo simulator
`VelaCanto Duo Test Sim`.
Freeze or otherwise identify the source before running the commands; a prior run
does not validate later edits. These commands use disposable isolation identities,
synthetic stores and no production startup or real account services.

## Local entry points

The owner approved a hosted-only exception for the existing quality workflow's
`pr-hosted` selection of a unique available iOS 27.0 `iPhone Air`. Prior GitHub
Actions job metadata and documentation support the `xcode-27` label as
GitHub-hosted. The script checks the GitHub Actions and CI environment, device
name, runtime and UUID; those checks do not themselves prove runner ownership.
Verify the actual runner and selected destination before any future hosted run.
Each hosted run remains separately authorized. Local commands continue to use
the single shared simulator.

Set `VELACANTO_PACKAGES_PATH` to the existing resolved package cache. For iOS,
set `VELACANTO_IOS_SIMULATOR_DESTINATION` to
`platform=iOS Simulator,id=<current Duo simulator UUID>`. For local commands the
gate requires the unique available `VelaCanto Duo Test Sim`, the iPhone Duo device
type and its matching current UUID. It never creates or erases simulators or
selects or boots another device. iOS 27.2 rejected Duo creation as incompatible;
the official iOS 27.1 runtime supports the dedicated Duo. Its initial bootstatus
reported `Data Migration Failed`, and Xcode logged an `invalidDigitCount`
runtime-version parsing diagnostic; both remain unwaived. A separate #201 test
passed its positive, expected missing-entry failure and restored-positive sequence
on that Duo. This does not establish a clean simulator environment or a pass for
this lifecycle gate. The separate #204 smoke script now checks the dedicated Duo
name, type and selected identity; actual UI smoke execution remains unverified.

- `scripts/build.sh isolation-test`: Mac lifecycle gate.
- `scripts/build.sh ios-simulator-isolation-test`: iOS lifecycle gate.
- `scripts/build.sh test`: ordinary Mac tests followed by the Mac lifecycle gate.
- `scripts/build.sh ios-simulator-test`: ordinary disposable iOS tests followed by
  the iOS lifecycle gate.
- `scripts/build.sh release`: both lifecycle gates before package checks.
- `scripts/build.sh pr`: the existing local combined checks. Its release phase
  reuses lifecycle gates already verified in the same invocation, with no
  duplicate suite execution. It does not add a hosted trigger or alter protection.

Set optional `VELACANTO_XCODE_JOBS=2` to bound local build concurrency. Unset or
empty preserves Xcode's default; other values must be canonical decimal integers
1 through 64. Test execution, shipping build settings and fresh-host preflight
remain unchanged. Use the existing resolved package cache and run the gates serially.

## Mac test-only IPC and signing

Xcode's Mac testing stage can inject a root-read exception and several Mach
services. The gate does not accept those broad test-host permissions. It
re-signs only the freshly built, identity-checked isolation host with the
reviewed sandbox, debugger and exact `com.apple.testmanagerd` lookup entitlement,
then performs signature/identity/entry-point/entitlement/test-plan preflight.
A real sandbox denial identified that one service as necessary for XCTest to
connect. Other Mach names, filesystem exceptions, networking, Keychain groups,
cloud groups and native entry points remain rejected. The entitlement is only
for the disposable Mac isolation target; shipping app entitlements are unchanged.

The normalization refuses other product paths and identities. A successful
preflight does not prove tests ran: the result parser separately requires the
reviewed static inventory (currently 201 shared lifecycle cases, 6 additional
Mac lifecycle cases and 12 widget-class cases: 213 iOS / 219 Mac) to be
present and passed, including finality, credential-generation, partial-removal
retry and replacement-task preservation cases. Missing, skipped,
failed or conflicting duplicate results fail the gate. Add new critical cases
to the explicit inventory as part of reviewing their implementation; never
derive requirements from an already-filtered result or silently reduce the list.
