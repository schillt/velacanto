# Home rebound end position follow up

Issue [207](https://github.com/schillt/velacanto/issues/207) remains open. On
2026-10-26 the owner reported that installed development build 218 still covers
Home's final row after a hard fling reaches the bottom and rebounds, expanding
the native navigation/player. The earlier normal/accessibility tests covered an
idle expansion triggered by tapping the collapsed Home tab. Their passes did not
establish acceptance of this different gesture path.

This isolated follow-up starts at `616a87a4853524bf2a5929b5dc8159dfcf19262c`,
including runtime integration `8c1275e`. It preserves installed applications and
the native tab-bar/accessory behavior. Maintainer preflight identifies the paired
iPhone 13 mini as running iOS 27.0.1; the retained simulator runs iOS 27.0. Physical
acceptance of the owner's reported path remains separate.

## Simulator reproduction boundary

Three bounded normal-size attempts used the production Home surface, a loaded
synthetic final album/title/subtitle, a synthetic queue and the isolated UITesting
identity. None tapped Home to simulate rebound expansion.

- The first fast swipe started at the top and did not establish overshoot from
  phase-boundary records. Its exercise assertion failed.
- A controlled start 90 points before the compact end overshot by 47 points,
  decelerated and rebounded. The native player remained minimized.
- A longer fast coordinate gesture overshot by 170.7 points, decelerated and
  rebounded. The player again remained minimized, so the strict automatic-expansion
  diagnostic failed its exercise assertion.

Those simulator outcomes do not reproduce the complete owner-reported sequence.
The maintained hard-fling regression requires actual overshoot and deceleration,
settled final-card clearance, three repeated gestures with stable observed native
placement, and a deliberate upward browse afterward. Its bounded trace identifies
each gesture and records the observed placement. Setting the test runner's
`VELACANTO_REQUIRE_REBOUND_EXPANSION=1` additionally requires automatic expansion;
a compact-only result cannot pass that diagnostic mode. The baseline failed
diagnostic artifacts remain private and are not converted into acceptance passes.

## Event ordering contract

The prior implementation rejected every non-idle viewport change and did not
reconcile geometry at the transition to idle. A focused regression preserving that
behavior ran seven tests: six existing tests passed and the new temporal case
failed because the idle callback returned no correction. It requires a viewport
change during deceleration followed by final idle geometry without another
geometry callback.

These tests construct temporal contracts from explicit geometry vectors. They
do not claim that the simulator captured automatic bar expansion during rebound,
or establish that this event ordering caused the owner's device report.

## End intent ownership

One view-owned, nonobservable tracker retains the latest geometry and at most one
pending end-resize candidate. Phase and geometry callbacks share that observation
order, so an idle context can expose the resize before its geometry callback, and
a later duplicate callback cannot repeat the point request.

The candidate requires that the same gesture had reached or overshot the end
before the bottom viewport shrank. It waits for idle, checks the current geometry,
and consumes once only if the remaining end loss fits the recorded viewport loss
within one local display pixel. It requests a framework-clamped concrete point,
not a persistent bottom edge anchor.

A fresh interaction, programmatic animation, deliberate interacting reverse drag,
changed content/width/top inset, restored viewport or moved-away end position
relinquishes that intent. A changed-then-restored layout cannot revive it. Reverse
motion during deceleration alone is treated as rebound, not a new user drag.
No correction runs during active scrolling. Geometry retained inside the plain
tracker does not publish per-frame SwiftUI state. The bounded extra trace is
DEBUG, simulator-only and explicitly fixture-enabled.

The modifier remains attached only to Home's outer vertical scroll view. Native
tab minimization, nested horizontal shelves, the accessibility mini-player label,
playback/queue ownership and independent optional-content publication remain in
their existing owners. Other browsing hosts are outside this follow-up's proof.

## Focused verification

The candidate's 15 focused macOS tests pass in 0.009 seconds, including both callback orders,
overshoot with later idle end loss, one-shot consumption, deliberate reversal,
new touch/programmatic movement, content/layout restoration, bounded loss and
absence of prior end ownership. The frozen candidate also passes all three native
iOS 27.0 cases: normal size (85.348 seconds), accessibility3 (93.566 seconds), and
three hard flings followed by deliberate upward browsing (67.373 seconds).
The two existing expansion cases retain strict final-card clearance and expanded
placement stability. The fling case retains measured overshoot/deceleration and
checks clearance and stability in the placement the system actually chooses.

Independent source review reports no actionable correctness/lifetime finding in
the scoped event contract. Formatting and whitespace checks pass. Private logs,
result bundles and synthetic captures remain in local milestone validation
evidence. These are focused topic checks; combined integration, signed artifacts
and installation belong to the maintainer's separate candidate record.

Exact-candidate physical reproduction/acceptance remains required. This local
follow-up does not close #207, prove the owner-reported cause, or authorize release,
publication or installation.
