## Product presentation

Library Songs on iOS/macOS adds one Sources picker, initially Jellyfin. Jellyfin
uses the complete existing native index, including its query/alphabet controls,
rows, downloaded projection and native pagination. All/Local are explicitly
sectioned bounded catalog presentations. All contains native Jellyfin song rows
and read-only local metadata; Local contains read-only local metadata only.
Search's See All Songs starts All with the current search query. Other Search
categories and overview ranking are unchanged. Unsupported adapter/fixture
implementations keep their functioning original native presentation; production
composition uses the existing concrete Jellyfin boundary.

Choose/Manage Local Library is a required callback into the existing library
sheet/importer, shared with the root toolbar. It cancels pending local detail
presentation before opening that sheet. No folder access or index refresh begins
merely by browsing or opening the sheet. File selection/refresh retain their
existing explicit user actions. The local details sheet contains metadata only.

The native index View owner remains mounted across source switches, retaining
its SwiftUI query/letter/model state, but a default-true body gate removes all its
contents while All/Local is shown. Thus an inactive source contributes no hidden
scroll view, search field, toolbar or loading modifier. Presentation is separate
from isActive, so backgrounding alone does not destroy its contents. The original
search/alphabet implementation is unchanged inside the body gate. The existing
iOS alphabet anchorRowID/anchorRevision remain owner state and the original
coordinator reapplies a changed anchor revision on construction. Free-scroll
pixel restoration is not proved: the previous coordinator's visible-anchor state
is ephemeral, and List/UIKit internal state can be recreated. Do not claim
complete scroll retention or platform UX acceptance before the native gate below.
Library All has a sectioned Songs presentation; it does not reuse an invisible
private query from Jellyfin-only. Search See All Songs is the combined-search path.

## Mutation, playback and ownership

A rendered Jellyfin control captures a typed item key, model owner and presentation
generation. Synchronous dispatch checks active/current query and library context,
exact account/source identity, current published membership and source capability.
Filter cycles and explicit refresh retire previously captured menus even if the
same ID is later published again. Root's current predicate also checks the actual
selected music-library object and account action owner's existing active scope.
That read-only action guard uses the already established opaque account scope;
it does not establish another lifetime owner or normalize identities.

Play dispatches to the existing player in the same actor turn, before optional
asynchronous binding work. Visible server tracks pass through existing
visibleTracks and FoundationTrackQueueSelection; local records never enter the
queue. Native row/menu actions remain Play/Next/Last, favorite, Add to Playlist,
download/cancel/retry/remove and related destinations. Add to Playlist requires
current catalog presence and the existing server-management capability/picker
permissions; it does not demand a playlist capability from a track.

Favorite actions recheck the captured intent inside their task. Related navigation
checks it before changing Handoff navigation state. Download removal carries a
typed request with its original current-context predicate into the stable host's
actual confirmation callback. Existing noncomposed controls keep the default
allowing predicate and their native action behavior.

The composed model captures existing favorite-read freshness before each remote
page and observes only newly fetched page items after publication guards. It does
not report the accumulated old snapshot as a fresh read. Offline mode uses the
existing caller's verified downloadedSongs/localSearchItems projection, makes no
server request and retires old intents when ready inventory changes. A mode change
invalidates the captured context. One aggregate verified-ready subscription is
used; no per-row observers or progress-triggered catalog queries are added.
Explicit pull-to-refresh resets result intent and starts both source tasks;
sections publish independently while the refresh indicator awaits completion.
