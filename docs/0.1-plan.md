# Velacanto 0.1.0 plan

## Outcome

Velacanto 0.1.0 proves the complete core music path on Apple platforms:

1. Open and play a device-local audio file in place.
2. Connect to a user-supplied Jellyfin server.
3. Authenticate a Jellyfin user securely.
4. Find and browse that user's music library.
5. Select and stream a track.
6. Control active playback and resume a signed-in session.

The first build number is `1`. The product version is `0.1.0`.

## Scope

### Included

- A SwiftUI app structured for iOS and macOS.
- Direct playback of one user-selected local file without importing, copying,
  indexing, uploading, or persistently bookmarking it.
- Manual server URL entry.
- Support for secure remote Jellyfin servers and explicitly handled local-network
  servers.
- Username and password authentication.
- Prompt-free token storage in Velacanto’s private app container.
- A stable, app-generated Jellyfin device identifier.
- Music library, album, and track browsing sufficient to select a track.
- Library-wide search across albums, artists, songs, and playlists.
- Streaming through Apple media frameworks.
- Play, pause, seek, and basic now-playing metadata.
- Background audio on iOS.
- Clear connection, authentication, empty-library, and playback errors.
- Unit tests for playback state and resource lifetime, URL validation, API
  request construction, decoding, session persistence boundaries, and core
  view-model states.

### Deferred

- Offline downloads.
- Playlist creation or editing.
- Queue editing beyond the selected album or browse context.
- Favorites, lyrics, casting, and transcoding controls.
- Multiple saved servers or users.
- Navidrome/Subsonic server connectivity. Its adapter is represented in the
  architecture, but Jellyfin is the first server implementation.
- CarPlay UI.
- Paid Apple Developer Program enrollment, TestFlight, App Store distribution
  and release automation, analytics, and third-party SDKs.

CarPlay is an intended platform, but it requires an Apple-approved managed
entitlement. It follows the proven phone playback path and must not block the
0.1.0 prototype.

## Technical direction

- Prefer Apple frameworks and Swift Package Manager.
- Use `URLSession` plus `Codable` for the initial Jellyfin API layer.
- Keep credentials and access tokens out of source control and logs.
- Store the token in a permission-restricted Application Support file; store
  non-secret server and session metadata in a small persistence layer.
- Use dependency injection at the networking, credential-store, and playback
  boundaries so core behavior is testable without a live server.
- Resolve source-specific selections asynchronously through adapters that hand
  a provider-neutral playback asset and temporary resource lease to one
  playback coordinator.
- Keep AVFoundation observation behind an injectable player engine so the
  coordinator responds to actual readiness, waiting, playback, completion, and
  failure state.
- Use an actor or otherwise isolated session/API client to make token and request
  state concurrency-safe.
- Use Apple playback, audio-session, now-playing, and remote-command APIs rather
  than a third-party player.
- Own the active player at app scope so navigation and view disappearance do not
  end playback.
- Keep iOS and macOS presentation separate where platform behavior differs while
  sharing models, API code, session state, and playback policy where practical.
- Add dependencies only when they remove more risk than they add.

## Delivery slices

### Slice 0: Project foundation

**Status:** Complete.

- Generate the app and test targets with the installed Xcode beta.
- Confirm deployment targets independently of the beta host toolchain.
- Set the bundle identifier to `com.chameleonenterprise.velacanto`.
- Use local Xcode-managed signing for physical-device tests without committing
  a team identifier.
- Add local-network privacy text and only the narrow transport-security exception
  required for user-entered local Jellyfin servers.
- Add a privacy manifest and keep it accurate as APIs and packages are added.
- Establish build, test, and formatting commands.
- Validate the shared playback path with direct local-file playback and an
  app-generated diagnostic tone.
- Keep 0.x deployment local and sideloaded. Use Xcode-managed Personal Team
  signing for physical-device testing where its provisioning limits are
  acceptable.

### Slice 1: Connect and authenticate

**Status:** Complete. The connect, authenticate, relaunch, restore, and logout
journey has been verified against a real Jellyfin server on a physical iPhone.
Negative-path device testing remains in Slice 4.

- Normalize and validate a server URL.
- Query public Jellyfin server information.
- Authenticate a username and password.
- Persist the access token and device identity securely.
- Restore the session at launch and support logout.

### Slice 2: Browse music

**Status:** Complete in code. Physical-device performance acceptance remains in
Slice 4.

- Locate the signed-in user's music libraries.
- Load useful first pages with cached metadata and shared artwork, then page
  ahead as the user scrolls.
- Open an album and show its tracks in server order.
- Cover loading, empty, retryable, and terminal error states.

### Slice 3: Stream and control playback

**Status:** Complete in code. Physical-device system-media and long-playback
acceptance remains in Slice 4.

- Resolve a playable audio URL and begin streaming.
- Show current item, elapsed time, duration, and play/pause state.
- Surface player readiness, waiting, completion, stalls, and playback failures.
- Handle audio-session interruption, route change, and app backgrounding.
- Publish now-playing metadata and artwork plus remote play, pause, previous,
  next, toggle, and seek commands.

### Slice 4: Stabilize 0.1.0

**Status:** Automated implementation checks pass. Physical-device/server
acceptance is pending.

- Exercise the happy path against a real Jellyfin server on iOS and macOS.
- Test bad URLs, denied local-network access, bad credentials, expired tokens,
  empty libraries, unsupported tracks, and network loss.
- Run unit tests and both platform builds from a clean checkout.
- Review logs for secrets and create a short known-issues list.

## Acceptance criteria

- A user can choose a local audio file, hear it without the file being copied
  into Velacanto, and release access by ending playback or replacing the active
  item.
- A new user can enter a Jellyfin URL, sign in, choose a track, and hear it.
- Relaunch restores a valid session without storing the password.
- Logout removes the stored access token.
- The app explains local-network permission and connection failures.
- Background iOS playback survives screen lock and supports play/pause from
  system media controls, with matching artwork and contextual previous/next.
- The same core session and browse flow works on macOS.
- Tests pass and no credential, token, provisioning profile, or local secret is
  tracked by Git.

## Project decisions

The platform baseline, macOS scope, local-HTTP policy, and Personal Team
sideloading policy are recorded in the decision records. The remaining project

```sh
./scripts/preflight.sh
```

reliable build impossible.
