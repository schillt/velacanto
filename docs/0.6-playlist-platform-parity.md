## Concrete gap addressed in this slice

Before this change, Mac sidebar playlist rows were plain navigation buttons with
no management context actions. Creation was available only after opening the full
playlist index. This was a missing native management path, not evidence that the
underlying Mac mutation implementation was absent. The new sidebar header and row
contexts reuse the accepted composer, picker and editor instead of introducing a
second mutation flow or hiding actions in an unrelated Profile setting.

Opening Playlist Details reveals the existing section directly. Rename/delete
results reconcile any currently displayed Mac playlist route so a deleted playlist
does not remain selected and a confirmed rename is reflected in its destination.
Open navigation items update only their title, preserving their existing header
owner identity and catalog identity. The sidebar observes destination identity,
so a confirmed title change does not cancel an unrelated pending queue addition.
All mutable work remains in the existing sheet-owned operation and authoritative
provider checks. Personal/server data is not mutated during this source audit.

## Shared reorder integration

This topic consumes #183 production commit `158611e` as an explicit dependency;
it does not duplicate its model/adapter logic. Both platforms expose Reorder Songs
from the playlist detail's More actions menu and the existing editor toolbar.
Mac also exposes it in the sidebar context menu. Unsupported/offline actions are
natively disabled. The nested editor uses one item-driven sheet destination for
Add Songs or Reorder Songs, and refreshes authoritative membership after dismissal.
The native test entry identifier is `playlist-reorder-songs` on the shared detail
action. #183 owns the synthetic mutable occurrence fixture and native reorder test.
