## Layout contract

This candidate starts from actual222 source `7a218652`. Home removes its consumer
of the programmatic scroll-position tracker. Existing historical implementation,
tests, failing builds and private evidence remain preserved. It now reserves
scrollable content extent from a shared root-local native chrome measurement.

A TabView background GeometryReader extends through the bottom container safe
area and measures that host's global frame. It is outside Home's content. The
native accessory publishes its actual content frame and normal/minimized
placement in the same global coordinate scope through the same root-owned model.
No screen-global size or hardcoded bar/player height is used. A host change
invalidates the accessory sample until its probe remeasures against the new host;
queue absence clears it. Invalid, unknown, disjoint, mixed-host or unmeasured
frames produce no extra reserve. A measured zero native inset is valid.

Home observes only the native bottom content inset, never offset for runtime
layout state. Additional reserve is `max(0, hostBottom - accessoryTop - nativeBottomInset)`,
rounded upward to the nearest local display pixel. The reserve is padding INSIDE
the LazyVStack. It changes content extent without changing the measured host or
adding itself to the native content inset. No safe-area inset is installed, so
there is no self-measurement loop. No native bar state, scrolling direction,
initial position, middle position, content publication or playback intent is
controlled by the model. Ordinary upward scrolling/minimization remains native.

## Isolated idle-only public UIKit adapter (source only)

This scope is deliberately idle-only. Tracking, dragging, deceleration or

the captured370.333/296.333 alternatives; intermediate offsets are not accepted

## One deferred application proposal implemented in isolation (uncompiled)

The next source-only experiment freezes one complete correction request and
queues one main-queue operation instead of setting the offset synchronously.
Apple documents the main queue as serial/FIFO; a hop leaves the current callback,
but is NOT a documented guarantee that every SwiftUI layout/restoration has
finished. See [DispatchQueue](https://developer.apple.com/documentation/dispatch/dispatchqueue).
Animation-completion hooks were rejected as a stronger seam because they may
complete immediately without animation. No delay, run-loop polling, timer,
second hop or retry is installed. A further native override rejects this prototype.

The request freezes current native content/bounds/frame/insets, natural revision,
chrome/root, local pixel and the same two exact allowed prior endpoints. One
pending token weakly captures its scroll view/window. Both intervening events
and queued execution revalidate ownership, enabled/visible scope, idle/native
motion, window identity and the exact frozen geometry/content/revision/chrome.
New tracking/navigation/scope/content/layout changes cancel. At execution a
current legal-end position is a no-op; an allowed retained/compensated endpoint
permits at most one nonanimated setter. The request is consumed before mutation.

The scheduling seam injects only the enqueue function; production always uses
one main.async. Attached active-scene UIScrollView tests hold and execute that
actual owner's queued operation deterministically. Seven iOS owner tests cover
restoration-before-execution/one setter/no retry, every non-idle phase, changed
geometry/content without another callback, newer user-away position, revision/
scope/chrome/scale changes, already-at-end no-op and detached/replaced identity.
The existing ten pure decision tests retain the same expected endpoints/targets.
Expected focused counts are Mac30 and iOS48; none have run for this new source.
Existing strict native clearance/upward assertions are unchanged.

Debug-only fixed stage/count/target facts distinguish scheduled, canceled,
already-at-end and applied observations inside the existing bounded opt-in trace.
No token/object identity or account/media values are logged. Main and installed
apps remain unchanged; issue207 and physical hard-fling acceptance stay open.
