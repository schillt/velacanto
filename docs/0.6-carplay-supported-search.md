## Platform constraint

Apple's [CarPlay framework documentation](https://developer.apple.com/documentation/carplay)
places CPSearchTemplate under navigation-entitlement-exclusive symbols. Its
[audio-app sample](https://developer.apple.com/documentation/carplay/integrating-carplay-with-your-music-app)
uses native lists, Now Playing and the play-media assistant cell. Generic keyboard
callback documentation and a successful template push do not establish support
for audio-app typing. The maintainer clarified this with the owner. The original
keyboard criterion must be reviewed as unsupported, not silently marked complete.
Phone/iPad/Mac search remains unchanged. No navigation entitlement, permission,
custom keyboard or forced Siri activation is added. No OS root cause is asserted.
The owner clarified that X is absent with empty text, so its behavior with entered
text has not been demonstrated.

## Supported production behavior

The CarPlay scene removes Type to Search, its CPSearchTemplate delegate,
keyboard/query lifecycle and query-only result rendering. Shared catalog search
and every other platform are unchanged. The DEBUG recorder type/schema/tests stay
internal history without scene wiring. Retained diagnostic220–222 sources and
private evidence remain preserved; no further keyboard experiment is proposed.

Search is a native list hub. Authorized Siri uses CPAssistantCellConfiguration's
playMedia action. Unauthorized Siri omits the inactive assistant cell and displays
disabled Enable Siri on iPhone guidance. Browse Library remains available in both
states, subject to native list limits. Configuration never requests authorization,
invokes voice capture, reads a catalog or starts playback. Inactive/hidden hub
row actions still complete the native callback without navigation.

Root Search has one explicit Close; pushed Search has one Back slot. Each pushed
hub owns its exact origin, including Now Playing and nested browse pages. Opening
Search above Now Playing creates a new hub even when root Search was selected;
it cannot pop Now Playing merely to reuse the root tab. Close returns to the exact
retained origin, otherwise to the last content tab. Browse Library selects the
existing Library tab. Native root/tab/single-pop operations retain browse models,
reject stale contexts/controllers and never reset queue/player/account state.

Startup presents the shared native Now Playing template once per connection,
after account/session readiness and successful current root installation. It
accepts native root-container/root-child representations, rejects stale contexts
and replaced roots, and does not override an already pushed destination. Later
model/account updates do not redirect browsing repeatedly. Existing queue/session
metadata and native empty-state behavior are used; no Play, seek, activation,
metadata clear or queue reset is added. Shelf loading remains independent.

## Reconciliation of local draft444

Useful one-shot startup and explicit root return behavior is reimplemented on the
current base. The fragile preselected-tab equality assumption remains excluded:
actual219 displayed Home despite preselected Library. Draft444's keyboard
presentation bridge is intentionally omitted with the unsupported typing path.
Its single shared origin is replaced with per-hub origins to resolve the observed
Now Playing/root-Search reuse defect. Historical constructed keyboard tests never
proved the persistent typing cause. Accepted issue16 and playback transport remain
preserved except the explicitly refined unsupported keyboard entry.
