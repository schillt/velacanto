# Velacanto 0.3 engineering record

The release behavior baseline is build 106, commit `3d66dbe8c9f0119f935c466585bd048f4e4d15b2`. Build 107 is excluded. The release replaces the legacy active app rather than maintaining two implementations; Git history and preserved archives retain prior work.

## Why the rebuild happened

The previous implementation accumulated playback preparation, coordination, admission, caching, retry, and recovery behavior while intermittent failures remained difficult to isolate. Diagnostics produced useful successes but did not establish the first stall's cause. The rebuild retained the design intent and useful architecture boundaries while starting with a minimal native Jellyfin player.

The active design uses one AVPlayer, neutral catalog items, an explicit Jellyfin adapter, native networking and Keychain, and SwiftUI presentation. It does not import the legacy candidate-player, preroll, cooldown, session-retirement, or recovery managers. Fewer mechanisms make behavior easier to inspect, but code deletion alone is not proof of improved reliability: delivery, workload, and feature scope also changed.

Provider-specific authentication and request models remain inside the adapter. These boundaries leave room for future providers without claiming a completed plug-in architecture.

## Development sequence

1. Established minimal native playback, an occurrence-based queue, sign-in restoration, and finite internal diagnostics. The owner reported successful direct selection and skipping.
2. Returned artwork and Library, then genres, favorites, pins, context menus, New, Search, and Home. Explicit collection queue additions load sequentially and cancellably before one complete addition.
3. Recreated artist and album pages with independent optional overview/recommendation sections, supplied artwork references, bounded shelves, native materials, and navigation.
4. Refined immersive Now Playing, safe-area artwork, metadata alignment, sheets, tabs, and contextual destinations. Volume, AirPlay, lyrics, and later system-media experiments remained outside accepted comparison builds when reliability was uncertain.
5. Preserved archives and stepped back to build 66, then restored delivery, seeking, and visual work independently through builds 98–106.
6. Build 107 added system metadata, remote commands, and artwork. Its 58 automated tests passed, but the owner reported failure during physical queue-history selection. It was rejected and build 106 restored.
7. The 0.3 package imports the build 106 behavior into the sole active Velacanto product. Production branding, bundle identity, project references, and release automation are packaging changes requiring fresh verification. No legacy credential migration is included.

## Evidence and uncertainty

Build 107 left player, delivery, audio-session, and transport source unchanged. It added system-media publication/command registration and one separately owned 640-pixel current-album artwork request. That request could duplicate visible artwork loading and could begin while a ready native item was still buffering.

The captured failed replacement did not reach ready/playing. Visible artwork later failed. Unscoped artwork operations consistent with the bridge had completed before the failed selection; the journal did not uniquely identify every system publication or remote-command origin. Neither those completed requests nor the additional workload alone proves causation.

Some historical failures recovered without intervention; others required a network reset. Those are different outcomes and remain recorded separately. Additional request overlap, native media-service behavior, cancellation, and device/network conditions are hypotheses. A common cause across volume, artwork, lyrics, and system-control experiments has not been established.

## Investigation boundaries

Further system-media work belongs in isolated candidates. Removing system artwork while retaining text and commands is a useful comparison, but would isolate the artwork feature rather than distinguish image transport from native image processing. Equivalent native-local and streaming sequences can help determine whether network delivery is necessary to provoke the issue.

No new retry manager, watchdog, automatic network reset, or speculative recovery layer is included in 0.3. Future evidence should add only missing bounded event attribution, preserve the exact artifact and reset history, and keep user media/account details out of shared reports.

## Replacement scope

Compared with the preceding alpha snapshot (`dd49d36f0bef691f2339855a56a42cb349402dfa`),
production Swift decreases from 42 files / 22,946 lines to 19 files / 5,767 lines.
These counts exclude tests, documentation, resources and dependencies. They describe
the replacement scope, not proof of reliability or a deletion target. The existing
106 app and test sources remain unchanged; formatting debt is recorded for later
cleanup rather than mixed into this release.
