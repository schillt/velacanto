## Diagnostic contract

- Compile only for DEBUG on iOS, and enable only with the explicit process argument
  `-diagnosticCarPlaySearch`. Normal launches do not resolve/create its destination.
- Keep at most128 events and a five-minute window. Expiration or the event cap does
  not rearm on later connection/input events. No observable per-event view state.
- The header records numeric app build and three numeric app/OS version components,
  resolved only after explicit opt-in. No device or account identifier is included.
- Typed events contain only relative elapsed time, a local numeric query ordinal,
  query length, ownership/current-context flags, a fixed top-template kind,
  navigation/success flags, result-row counts and native-completion counts.
  No query text, credentials, URLs, account/media/device IDs or arbitrary errors
  are accepted by the schema.
- Preserve existing guard evaluation order and return values. The existing native
  top-template read is reused; no additional native IPC read is added per key.
  Native completions and playback never await diagnostic encoding or I/O.
- Coalesce one pending typed snapshot behind one serial utility writer. Limit the
  encoded file to1MiB. Use protected atomic replacement and explicit backup
  exclusion in `Library/Caches/CarPlaySearchDiagnostics/current.json`.

The maintainer exports the private file through `devicectl device copy from` with
the app-data-container domain and the existing canonical app identity. Verify the
actual launched build/arguments and file freshness before interpreting a trace.
The numeric header supports stale-build rejection but does not identify a signed
artifact or establish
physical file-protection/backup behavior.

## Lifecycle observation follow-up after owner build220 reproduction

Private build220 schema1 evidence contains an accepted empty update, one completed
empty response and a successful keyboard push. It contains no later text callback.
The owner reports typing and exiting remain unusable. This does not establish a
query resolver or early-guard cause. In particular, `cancelWork()` could remove the
weak search delegate directly without the old retirement event.

This schema2 follow-up observes both actual `cancelWork` callsites before mutation,
plus the stale push-completion delegate-removal branch and ordinary retirement.
Each event retains only booleans and fixed numeric fields. `removalReason` is1 for
disconnect,2 for prepare and3 for stale push completion. `contextMismatch` is a
seven-bit mask:1 missing search context,2 missing controller,4 generation mismatch,
8 player mismatch,16 actions mismatch,32 catalog-scope mismatch,64 local-only
policy mismatch. Only comparison results are retained; identities and values are
never encoded. `contextRetained` and `delegateOwned` capture the retained context
and exact native search-delegate ownership before removal. Push completion also
captures ownership. Initial push records the already-proven unrestricted state;
restriction callbacks record the supplied keyboard flag before their normal guard.
No extra native restriction or top-template property read is added.

Optional UIKit scene callbacks record fixed `sceneEvent` numbers:1 became active,
2 resigning active,3 entering foreground,4 entered background. These are native
lifecycle notifications, not inferred focus or input delivery. No timer, polling,
forced foreground activation, template change or search behavior is added. DEBUG,
explicit opt-in,128-event/five-minute limits and the existing protected writer are
unchanged. No minimal native fixture is included.

The existing schema/write test now requires numeric lifecycle metadata and schema2.
Source formatting and whitespace checks pass; compilation/tests and a new exact
build trace remain maintainer-owned gates. A lack of later events does not prove
native input health or rule out an unobserved process/session boundary.
