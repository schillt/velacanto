# Private Home rebound device diagnostic

The owner confirms the same Home final-row overlap in development builds 218 and
219. Both fail physical acceptance for issue207. The earlier simulator results

## Activation and scope

The recorder is compiled only in DEBUG. Its live provider is iOS-only and requires
the exact launch argument `-diagnosticHomeRebound`. It uses the normal application
and existing account/data identity. It neither requires nor enables fixtures,
`-foundationTesting`, synthetic downloads or a new signing/storage identity.
There is no persistent tracing preference or new application UI.

The maintainer prepares and signs a separate diagnostic Debug build 220 after
review. This topic does not change version metadata, install or launch an app, or
authorize publication. Native bar/accessory behavior, end-preservation decisions,
playback, queue, loading and account lifecycle remain unchanged.

## Bounded private trace

The capture window starts when Home first becomes active and expires after five
minutes. Re-entering Home never restarts an expired window. Home inactivity pauses
collection. Memory retains at most 1,024 records from the latest four gestures;
the private JSON file is at most 1 MiB. Eviction, sampling and encoding-truncation
counters identify incomplete history. Routine geometry/frame observations are
sampled at most 30 Hz per source; phase, layout and changed-decision events bypass
sampling within the same finite record budget.

Records contain relative elapsed time, a local gesture number, fixed enums and
numeric quantities only:

- Previous/current scroll content offset, content/container size, all content
  insets, bounds, visible rectangle and derived unobscured bottom.
- Actual phase callbacks, tracker candidate/reached-end state, diagnostic rejection
  or cancellation reason, candidate end-offset/viewport facts and issued point
  requests. Reason explanations do not control the existing policy.
- Published native accessory placement and measured public accessory-content
  global frame. This frame is not a measurement of the private system capsule.
- Home viewport and content global frames. Cached initial measurements include
  their age; a placement change clears an old accessory frame until a new frame
  is measured. Raw geometry records label the latest observed phase.
- Numeric app version/build and OS version. No device, account, catalog, media,
  credential or server identifiers, titles, URLs, error descriptions, screenshots
  or absolute filesystem paths enter the trace.

A nonobservable recorder keeps the trace; observations publish no per-frame
SwiftUI state. Snapshot encoding and file I/O run on a utility queue, with at most
one write and one coalesced pending snapshot. An idle snapshot is flushed after
250 ms so it includes post-request geometry; a new active phase cancels that
pending flush. Home exit/background inactivity and expiry flush immediately.
Scrolling and audio never await file completion.

The single file is
`Library/Caches/HomeReboundDiagnostics/current.json` inside the existing app's
private data container. The directory is excluded from backup; iOS writes use
atomic replacement and protection until first user authentication. Only an
explicitly opted-in recording creates/writes this file. Re-launching with the
argument starts a new bounded recording and replaces this diagnostic file, not
account data. Without the argument the live recorder is absent. Release exclusion
checks reject its unique launch, type and directory markers.

## Maintainer reproduction and export

After the frozen diagnostic build passes focused checks and signing review, the
maintainer launches it on the already authorized paired phone with the opt-in
argument, preserving the normal bundle, groups, data and credentials. The owner
then reproduces the real Home fling/rebound once while the five-minute window is
active. Before asking for reproduction, a targeted export should confirm the
diagnostic header has the intended build and a Home-entry record. No synthetic
path substitutes for the owner's observation.

The supported targeted export is:

```sh
xcrun devicectl device copy from \
  --device <authorized-paired-phone> \
  --domain-type appDataContainer \
  --domain-identifier <existing-phone-bundle-id> \
  --source Library/Caches/HomeReboundDiagnostics/current.json \
  --destination <private-local-evidence-file>
```

The CLI help confirms this file/domain route; an actual phone export remains a
separate verification step. Export only this file, not the whole app container or
other debug journals. Raw evidence stays private. Review whether the candidate
armed, why it relinquished/rejected end intent, whether a point was issued and
how the actual geometry and native placement responded before proposing a fix.
